# BEYBLADE X｜戰鬥陀螺收藏智慧中心

以收藏者實際持有的九組商品建立第一版資料庫，共 **19 顆**：BX 7、UX 5、CX 7。

## 功能

- 收藏圖鑑：依 BX／UX／CX、日／美版篩選與搜尋。點卡片可看原廠配置。
- 配件庫存：計算實體戰刃、固鎖、軸心及 CX 模組。
- 組裝模擬：建立最多三顆的隊伍。支持 BX／UX 完整戰刃、CX 原廠完整戰刃與 CX 紋章／主刃／輔助刃自由搭配。
- 零件占用檢查：同一個**實體**零件不可同時出現在同一份隊伍的多個槽位。
- 配置保存：瀏覽器 LocalStorage 保存，並提供 JSON 備份匯入與匯出。
- 本機新增：可暫時新增收藏，之後需將備份更新至 GitHub 才能跨裝置共享。

## 啟動

網站是純靜態頁面。開啟 `index.html` 即可瀏覽，也可將專案部署至 GitHub Pages。

在 GitHub 專案的 **Settings → Pages**，選擇 **Deploy from a branch → main → /(root)** 並儲存。

預期網址：`https://hey966.github.io/BEYBLADE-X/`（需先啟用 GitHub Pages）。

## 資料與分析

- `data/collection.json`：實體收藏清單，含 19 顆、9 組與逐顆配件。
- `data/image-sources.json`：原廠型號、每個零件來源與圖片路徑。
- `data/part-abilities.json`：根據發售版本配對的能力資料（19 顆、78 筆配件）。
- `data/part-abilities.js`：同一份能力資料，供純靜態網頁直接使用。
- `tools/sync_part_abilities.py`：從公開資料庫讀取各個零件的 `defaultStatus` 欄位，不填補缺失值。
- `analysis.js`：顯示能力視窗、自動配裝及對手克制推薦。
- `app.js`：收藏、配件、手動組裝與本機保存。

能力來源：
- https://beyblade.phstudy.org/data/hasbro.json
- https://beyblade.phstudy.org/data/main.json
- 官方遊戲說明：https://beyblade.takaratomy.co.jp/beyblade-x/guide/

**能力數值的解讀**
資料庫紀錄的是公開發售版本所列的零件能力指標，非實測強度、重量測量值或獲勝機率。不同零件的數值角色不同。標為 0 的部分指標，不代表配件完全沒有作用。未知或不存在的欄位不會憑空補上。

**推薦演算法（經驗式權重）**
以完整 BX／UX 戰刃或 CX「紋章＋主刃＋輔助刃」組合為上層，搭配每一個實體固鎖與軸心。CX 模組使用公開數值的加總。下列係數是站內的排序假設，不是官方公布的勝率公式：

- 攻擊向量 = 戰刃攻擊×0.62＋固鎖攻擊×0.12＋軸心攻擊×0.26＋軸心衝刺×0.17。
- 防禦向量 = 戰刃防禦×0.62＋固鎖防禦×0.15＋軸心防禦×0.23＋軸心爆裂抗性×0.08。
- 持久向量 = 戰刃持久×0.62＋固鎖持久×0.13＋軸心持久×0.25。
- 攻擊排序：攻擊向量×0.78＋衝刺×0.22（加上類型一致加權）。
- 防禦排序：防禦向量×0.76＋抗爆×0.15＋持久×0.09（加上類型一致加權）。
- 持久排序：持久向量×0.85＋防禦×0.15（加上類型一致加權）。
- 平衡排序：向量平均×0.43＋三項最低值×0.36＋抗爆×0.21（加上類型一致加權）。

類型由軸心決定，僅用在「一般自動配裝」的攻擊、防禦、持久與平衡篩選；**「能力壓制分析」不使用類型相剋來決定配置**。

### 能力壓制分析（2026-11-16）

使用者只需選擇對手 **1 顆或 3 顆**。選 1 顆固定推薦 1 顆（1 對 1）；選 3 顆固定推薦 3 顆（3 對 3），沒有獨立的我方數量選單。對手每顆均可獨立選戰刃、固鎖、軸心；CX 可另選紋章、主刃、輔助刃。先將每一組實際零件轉為攻擊、防禦、持久、衝刺、抗爆能力向量，再逐一比較：

- **進攻壓力**＝我方攻擊＋0.30×我方衝刺－（對手防禦＋0.15×對手抗爆）。
- **防守承受**＝我方防禦＋0.24×我方抗爆－（對手攻擊＋0.25×對手衝刺）。
- **持久差距**＝我方持久＋0.12×我方防禦－（對手持久＋0.12×對手防禦）。
- 依對手實際攻防持久分布調整三項權重，再計入雙方抗爆與衝刺差距。50 分是此模型的中性基準。結果是**相對壓制模型分，不是勝率**。
- 單顆對單顆時，直接比較完整能力。演算法保留多對手的通用評分計算方式，但目前介面只提供 1 對 1 與 3 對 3。
- 三顆配置時，採候選搜尋、能力覆蓋與 3 對 3 指派評分，並以每個實體零件 ID 排除重複占用。演算法是啟發式最佳化，不保證找到所有可能組合中的全域最佳解。
- 結果會列出每名對手的完整能力向量、我方建議配置、雙方各項相對差距，以及隊伍壓制覆蓋情形。

上述權重是站內建模假設，不是官方賽事勝率公式。尚未納入實物重量、碰撞角度、發射力度、競技盤、磨損、特定特殊機制與全部賽規相容性，需透過實際對戰驗證。

## 新增實體收藏的流程

1. 依照片確認商品代碼、發售市場、各零件與旋轉方向。
2. 在 `data/collection.json` 新增實體，並同步 `data.js`。
3. 在 `data/image-sources.json` 建立每個獨立零件的精確來源 ID 和照片。
4. GitHub Actions `reference-images.yml` 產生透明 PNG；`part-abilities.yml` 更新配件能力與網站資料。
5. 核對自動配裝的實體零件不重複、照片版本正確、分析資料不是臆測。

本機新增不等於 GitHub 已自動更新。若只在瀏覽器新增，沒有核對來源的零件不會參與能力推薦。未來收到新照片後，需要同步上述原始資料，網站才能包含新收藏。

> 注意：這是個人收藏分析工具。CX 互換、左旋兼容及特殊零件的實際合法性，仍需依當期官方賽規、零件限制和實體測試核對。



## 圖片來源與透明 PNG 狀態（2026-11）

* 本站使用 `data/image-sources.json` 登記逐顆查核的第三方商品照片及各零件來源。
* `tools/create_png_assets.py` 與 GitHub Actions 只在來源可正確下載、可可靠去背時，才生成對應透明 PNG。
* `data/image-status.json` 紀錄成功、人工審核或仍缺圖的圖片。缺圖不會以錯誤陀螺代替。
* 19 顆分為 9 個原始商品套組；Marvel G3063 的兩顆仍在尋找可用的獨立商品圖。
* 日本版 UX-08 SilverWolf 已登錄本體、3-80 固鎖與 FB 軸心三張透明 PNG。
* 圖像所有權屬原權利人。若用於公開網站或再散布，應確認圖片的授權範圍。


## 模擬對戰 V1（能力驅動原型）

已新增「模擬對戰」分頁。依目前收藏的零件能力數值執行動態計算。

- **1v1、3v3**：三顆按照出戰序號依序一對一，累積 4 分。平手重賽同一對。
- **自訂配件**：戰刃、固鎖、軸心；CX 可選紋章、主刃、輔助刃。檢查實體配件與同型號重複。
- **發射參數**：拉線／拉條、0～14000 SP 模擬力道、發射角度。旋向由戰刃資料決定；模擬假設已使用相容發射器。
- **場地**：Xtreme 盤及練習盤；以簡化動力模型處理移動、衝刺、碰撞與終結。
- **即時畫面**：Three.js 3D 通用陀螺和競技盤。WebGL 或 CDN 失敗時改 2D。支持暫停、下一回合和倍速。
- **大量模擬**：25／100／500／1000 場、固定種子可重現。匯出 JSON。
- **自動新增**：未來新收藏需先有經查核的配件能力數值，才能加入此計算；尚未驗證者不會使用猜測資料。

完整模型、資料界線、方程及限制，見 **[V1 技術規格](docs/simulation-v1.md)**。

**V1.1 介面修正：** 已加入「重置對戰設定」，場地切換會同步變更 3D／2D 競技盤與引擎參數；畫面使用實際選用的戰刃、CX 模組透明 PNG 作近似外觀。下方另展示固鎖、軸心的來源照片。每次先顯示模型判定的停轉、出界或爆裂動作，再更新比分。詳見 [V1.1 變更](docs/simulation-v1.md#v11-修正畫面與計分一致性)。

**此原型的質量、摩擦、碰撞與爆裂參數尚未量測校正。模擬結果不是實戰勝率，3D 模型也不是各顆陀螺的精準外形。**


**V1.2 重播視覺與聲音（2026-11-16）：** 對照使用者提供的手機影片，改為藍色網格背景、白色多層競技盤及螢光綠 Xtreme Line。實際模擬的 hit／dash／finish 事件會同步產生火花、衝刺光效、移動軌跡與短暫鏡頭震動。新增原創程序合成的發射、旋轉、碰撞、導軌衝刺、爆裂、出界和勝負音效，以及音效開關、音量控制。瀏覽器需經使用者點擊後才能發聲；批次計算靜音。詳見 [V1.2 技術紀錄](docs/simulation-v1.md#v12-戰鬥重播風格與音效依使用者參考影片)。

**V1.3 左右半場投放與 SP（2026-11-16）：** 即時畫面維持完整連續的競技盤，不顯示半場色塊或中心分界線。雙方從上方投放，依固定亂數種子落在各自半場並輕微回彈。落地後不受中線阻擋，可自由碰撞。發射操作改為 0～14000 SP 滑桿及精確數字輸入（重置為 10500 SP），兩種畫面與批次計算共享模型。SP 是網站內部的可調參數，並非官方硬體量測換算。詳見 [V1.3 技術紀錄](docs/simulation-v1.md#v13-左右落點區落地彈跳與-sp-操作2026-11-16)。

**V1.4 撞擊動態與角度修正（2026-11-16）：** 修正過於平靜的對戰。發射角度會影響初速方向與可見傾斜，調整滑桿時可即時預覽。碰撞會出現更明顯的反彈、短暫騰空、失衡傾斜、火花及鏡頭回饋；撞擊負荷依攻擊、防禦與爆裂抗性累積，有機會造成爆裂或擊飛。3D 爆裂時零件分離，2D 備援同步繪製拆散狀態。原先不可見的左右發射區維持不變。這些是增強表現力的**未實測物理假設**，不能作為真實勝率。
